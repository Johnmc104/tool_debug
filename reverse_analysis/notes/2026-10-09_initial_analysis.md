# 2026-10-09 初步分析记录

## 目标与边界

用户希望改为研究 FSDB 自行解析，最终在单机本地使用，不依赖许可证。本阶段进行静态分析与最小读取实验，保存证据并写可行性报告；主工程实现未修改。

## 过程

1. 核对 vwave 当前 API 调用面：30 个不同的 `npi_fsdb_*` 名称。vsignal 属于 KDB / RTL 网表解析，不在本次 FSDB 实验范围内。
2. 检查本机 Y-2026.03-SP2：发现 NPI 与独立 `share/FsdbReader` SDK。选取 `libNPI.so`、`libnffr.so`、`libnsys.so`，记录 SHA-256、ELF 和符号。
3. 检查现有 23092 字节 FSDB 样本，保存文件头、ASCII 片段位置、每 1024 字节的信息熵。样本包含 T-2022.06-SP2 写入器文本。
4. 从完整符号表定位 NPI open 包装与 reader 文件头、层次树、解压函数。只读局部反汇编，未修改库。
5. 编写 `reader_probe.cpp`，仅调用 reader API，提取层次与指定信号事件。
6. 首次仅链接 `-lnffr` 失败：其存在对 `libnsys` 的未解析引用。失败日志保留于 `evidence/probe/build_without_nsys.failed.log`。补充 `-lnsys` 后仍需 zlib / dl，最终链接参数见实验脚本。
7. 首次使用 `tb_top.clk` 未命中；树回调显示实际顶层为 `tb`，改为 `tb.clk` 后完成读取。文件名 `tb_top.fsdb` 不能作为顶层名称依据。
8. 实验子进程将 License 地址设为 `1@127.0.0.1`，用 `strace -f -e trace=network` 观察运行。成功输出 132 条时钟事件，跟踪未出现网络调用。
9. 交叉核对现有测试脚本中的预期：scale 为 1ps、max_time 为 3275000、时钟变化数为 132。没有运行新的 NPI 对照查询，不能宣称已逐事件与 NPI 比较。

## 已确认与待验证

已确认：当前样本能通过 reader SDK 在不调用 NPI、未观察网络连接的条件下读取。自研 parser 仍未实现。

下一步先建立可控小样本，再解析固定头与块目录，随后尝试层次树和一位数字信号事件。解压路径包含多种分支，需确认样本具体采用哪一种；发现 AES 调用并不表示当前样本已加密。

所有后续结论应记录样本哈希、reader 版本、命令、预期与实际输出。偏移假设要区分磁盘偏移、解压后缓冲区偏移与 C++ 对象内存偏移。
