## 2. 版本差异

### 2.1 NPI 目录与库

| 项目 | T-2022.06-SP2 | Y-2026.03-SP2 |
|------|---------------|---------------|
| 头文件 / 库路径 | `share/NPI/{inc,L1/C/inc,lib/linux64}` | 相同 |
| 新增头文件 | — | `npi_sdb.h`、`npi_upf.h`（2024 起） |
| 新增库 | — | `libNPI_base.so`、`libvfs.so` |
| 预编译 GCC 版本 | 7.3.0 | 12.3.0 |
| `npi_init` / `npi_end` 签名 | `int npi_init(int&, char**&)` | 相同 |

- 2026 库要求 GLIBC ≤ 2.28，本机 glibc 2.28 满足。
- 本机 GCC 9.5 的 libstdc++ 可满足 2026 库的符号需求，链接与运行正常。
- `libvfs.so` 为 `libNPI.so` 的 NEEDED 依赖，经 NPI 库自带 RPATH（`$ORIGIN`）解析，Makefile 的 `LIBS` 无需增加。

### 2.2 License feature 变更（关键差异）

| 版本 | `npi_init` 签出的 feature |
|------|--------------------------|
| T-2022.06-SP2 | `Verdi 2022.06` |
| Y-2026.03-SP2 | `VerdiNPI 2026.03` |

2026 版 NPI 改为签出独立的 `VerdiNPI` feature。License 服务器若无此 feature：

```
FlexNet Licensing checkout error: No such feature exists.
Feature:       VerdiNPI
p: Failed to check out license!
[NPI ERROR] Please call npi_init() before npi_fsdb_open.
```

`npi_init()` 返回 0，后续所有 NPI 调用失败。

**回退方案**：设置环境变量 `NPI_LICENSE=Verdi`，2026 NPI 会回退签出 `Verdi` feature（已验证 `Checkout succeeded Verdi 2026.03`）。注意：取值为 `1` 时不生效。

```bash
export NPI_LICENSE=Verdi   # 仅在 License 服务器无 VerdiNPI 时需要
```

## 4. 验证过程中暴露的问题（与 2026 适配无直接关系）

### 4.1 [高] NPI 初始化失败被静默吞掉

`src_vwave/server/server_core.h`、`src_vsignal/server/server_core.h` 中未检查 `npi_init()` 返回值；vsignal 也未正确处理 `npi_load_design()` 失败场景。License 签出失败时：

- vwave：`open` 报 "Server process exited unexpectedly"，用户需翻日志才能定位到 License 问题。
- vsignal：日志打印 `Design loaded successfully`，daemon 正常启动，**所有查询返回空结果且 status=ok**，极具误导性。

**建议**：检查 `npi_init()` 返回值，失败时立即退出并输出明确提示（License 签出失败、`SNPSLMD_LICENSE_FILE`、`NPI_LICENSE=Verdi` 回退方案）；`npi_load_design()` 失败同样退出。

### 4.2 [中] LD_LIBRARY_PATH 覆盖 RUNPATH，导致跨版本误加载

Makefile 使用 `--enable-new-dtags` 生成 RUNPATH，其优先级低于 `LD_LIBRARY_PATH`。当前环境 `LD_LIBRARY_PATH` 包含 2026 NPI 库目录，以 2022 编译的二进制会加载 2026 库：

```
*WARN* Resource file: Incorrect version "Verdi_T-2022.06-SP2". Need "Verdi_Y-2026.03-SP2".
vsignal: Failed to check out license!
```

`src_vsignal/main.cpp:142` 的 LD_LIBRARY_PATH 自动补全也存在同类风险。

**建议**：改用 `-Wl,--disable-new-dtags`（生成 RPATH，优先于 LD_LIBRARY_PATH），或在 `open` 时校验加载的 NPI 版本与编译版本一致。

### 4.3 [低] Makefile 默认 VERDI_HOME 过时

`Makefile:42` 默认值仍为 `/opt/Synopsys/verdi/T-2022.06-SP2`，当前能编到 2026 仅因环境变量 `VERDI_HOME` 已设置。

**建议**：默认值更新为 `Y-2026.03-SP2`，`make help` 中注明支持版本。

### 4.4 [低] 既有输出缺陷（2022 / 2026 一致）

- `conn` 输出 `port` 字段为空字符串。
- `driver --full` 对 inst_port 类型无 `file` / `line_*` 字段。

非版本回归，可在后续迭代处理。

### 4.5 [低] 测试脚本二进制路径错误

`test_vwave/run_test.sh`、`test_vsignal/run_test.sh` 引用 `build/bin/`，而实际输出目录为 `release/bin/`，`make test` 无法正常运行。

**建议**：改为 `release/bin/`，或由 Makefile 通过环境变量传入 `BIN_DIR`。

## 6. 修复说明

- **新增 `src_common/npi_env.h`**
  - `sync_verdi_home()`：编译时 Verdi 路径（`-DTW_BUILD_VERDI_HOME`）存在时，fork 前将 `VERDI_HOME` 对齐到该路径，与用户值不一致时给出警告；部署到其它机器、编译路径不存在时保留用户 `VERDI_HOME`。
  - `ensure_npi_lib_path()`：由 vsignal `main.cpp` 迁移而来，基于对齐后的 `VERDI_HOME` 补全 `LD_LIBRARY_PATH`。
  - `report_init_failure()`：`npi_init` 失败时输出 License 排查提示。
- **server_core.h（vwave / vsignal）**：`npi_init()` 返回 0 时报错退出；vsignal `npi_load_design()` 判定改为 `<= 0`。
- **daemon.h**：server 异常退出时，客户端直接回显日志中的 `ERROR` / `Hint:` 行。
- **Makefile**：默认 `VERDI_HOME` → Y-2026.03-SP2；`--enable-new-dtags` → `--disable-new-dtags`（RPATH 优先于 LD_LIBRARY_PATH）；`make test` 通过 `BIN_DIR` 传入二进制目录。
- **handlers.h（vsignal conn）**：port handle 无 `npiFullName`，回退 `npiName`。
- **测试脚本**：二进制路径改为 `${BIN_DIR:-release/bin}`；vwave `open` 超时放宽到 60s（License 签出约 20s）；同步 T8 断言（name 为 leaf 名，见 20aae0d）与 vsignal 断言（`count` → `total`，见 61f98a6）；新增 conn port 名断言。
